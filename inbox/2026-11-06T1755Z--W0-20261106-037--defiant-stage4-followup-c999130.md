## A. Fix the incorrect exact-replay comparison

In `XaveriusRegistryRegisterDdxDevice()`, the new exact-replay condition compares:

```c
existing->binding->binding_generation ==
    registration->module_role_generation
```

This is invalid: a binding generation and a ModuleRole generation are distinct generation domains. Never compare them or treat them as interchangeable.

Define exact replay only from fields that the registration API actually supplies and that the normative spec says establish the same live registration/binding ownership. The current registration descriptor has no caller-supplied binding generation, so do not fabricate one or compare unrelated generation values. If exact same binding ownership cannot be proven from the supplied registration and current role, return the normative identity-conflict result without modifying the existing record or taking a reference. A tombstone is never an exact live replay. Preserve W0-034's distinct-incarnation rule.

Tests must cover:
- same identity with same exact eligible live registration/owner, according to the normative definition;
- same identity with another role generation;
- same identity with different native handle/context/ops ownership;
- tombstone followed by same-identity re-registration;
- prove conflicts do not mutate either record or leak/retain references.

## B. Complete the ops-table deep copy (or do not claim it)

The new `xaverius_binding_alloc()` allocates and memcpy-copies only the top-level `XaveriusDeviceBackendOps`. Its four nested pointers (`buffer_memory`, `shader_pipeline`, `commands`, `synchronization`) still point into DDX-owned memory. This is not a deep copy and becomes dangling if the DDX module's storage is unloaded.

Implement server-owned immutable copies of every required nested typed table, with a single clear binding-destruction/unwind helper that frees all copies exactly once. Set the copied top-level table's nested pointers to the server-owned copies. Validate descriptor size/version and all mandatory callbacks/table pointers/entries before copying or invoking anything; validate capability-relevant optional entries according to the normative profile. Do not blindly copy a short/unknown table or assume a non-NULL pointer is a valid table.

Tests must mutate or invalidate the original DDX table storage after successful registration and prove the binding's copied tables remain intact; test allocation failure at each copy step and exact cleanup.

## C. Balance every ModuleRole retain on every failure

The current path calls `XaveriusModuleRoleRetain(role)` before `xaverius_binding_alloc()`. If that allocation fails, it returns without releasing the role. The subsequent `dev` allocation and identity/snapshot failure paths also free only part of the provisional state; for example, `free(binding)` does not free the newly allocated `binding->ops`, and the retained role is not released.

Use one failure-atomic provisional-registration cleanup path. It must release exactly the resources acquired so far, including every nested ops copy, provisional snapshot, identity copy, binding allocation, and the retained ModuleRole reference. Do not release a reference that was never acquired, and do not publish/list-link a partially initialized object.

Add deterministic fault-injection tests for each allocation/callback failure after retain. Assert exact ModuleRole retain/release counts, no registry-list mutation, no leaked provisional allocation, and output sentinels.
