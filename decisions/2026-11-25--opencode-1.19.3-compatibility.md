## Upstream API cross-check

The upstream OpenCode repository tag `v1.19.3` was inspected:

- `packages/plugin/src/index.ts` declares the legacy `chat.params` and
  `experimental.chat.system.transform` hooks.
- `packages/sdk/js/src/gen/sdk.gen.ts` exposes
  `client.session.promptAsync()` on `/session/{id}/prompt_async`; its API
  comment says it starts a session message and returns immediately.
- `packages/sdk/js/src/gen/types.gen.ts` defines `message.updated` and
  `session.idle`. The latter carries a session ID, not a Comms event or
  message ID.

## Decision and consequences

- Treat OpenCode CLI/runtime 1.19.3 and plugin SDK 1.19.3 as the verified
  compatibility baseline for the current representative fleet deployment.
- Keep the existing legacy V1 plugin hooks and `promptAsync` adapter for the
  incremental Comms event-pipeline migration. Do not migrate to V2 based only
  on newer documentation.
- A successful `promptAsync` return proves submission API acceptance only.
  `session.idle` is session-scoped and cannot, alone, prove completion of a
  specific directive. Lifecycle reporting must correlate a specific event
  through observable turn start and completion evidence.
- Re-check the version on another ship before assuming the entire fleet is
  homogeneous.
