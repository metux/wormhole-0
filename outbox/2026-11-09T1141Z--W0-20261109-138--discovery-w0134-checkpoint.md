### Gap-by-gap result

1. **Repository-relative spool / repo selection.** Spool root is
   `<configured-checkout>/mail`; every publish/transition uses that repository's
   configured remote and branch. No hardcoded `origin master`, no parent-dir
   repository. `wormhole send --repo` selects an explicit enabled repository;
   otherwise the first enabled one.
2. **Durable transitions and error propagation.** Publish, `new -> cur` claim,
   `cur -> processed`, and `-> failed` are each a separate exact-path commit +
   push. Source deletion and destination addition are staged together. A push
   failure aborts before import; a claim that is not pushed is never imported.
   Commit/push errors are returned to the cycle caller.
3. **One repository-scoped lock.** All Git writers (sync and spool lifecycle)
   use the same per-repository `flock`; the spool is repository-specific and
   has no process-local mutex or global singleton. Test asserts a second writer
   cannot acquire the same repository lock.
4. **Sender path.** `starfleetctl wormhole send --to <ship> [--repo <id>]
   [--from <ship>] [--subject <s>] [--text <t>|--stdin]` writes immutable bytes
   atomically into `mail/<target>/new/<id>` and durably commits+pushes that
   exact path. `wormhole sync` is now a real one-cycle sync+process, not a stub.
5. **Retry/failure classification.** `Bus.PostExternal` errors are treated as
   transient: the message stays recoverable in `cur/` with no arbitrary retry
   cap. Only permanent local validation failures (malformed envelope,
   id/filename mismatch, recipient/mailbox mismatch, claim collision) move to
   `failed/`, together with a durable `<name>.reason` diagnostic committed and
   pushed with the move.
6. **Stable identity and exact payload.** `PostExternal` receives the configured
   repository ID as `source`, the immutable message ID as `externalID`, and the
   exact original file bytes as `text` (never a reconstructed content field).
7. **Removed legacy configuration.** `outgoing`, `incoming.messages`,
   `incoming.decisions`, `paths`, and `target_aliases` are no longer allowed;
   tests assert each is rejected as an unknown key.
8. **Evidence.** New tests cover: remote commit/push durability, byte-exact
   pushed payload, idempotent republish, collision fail-closed, recipient
   authorization failure with durable diagnostic, malformed message isolation,
   transient import failure left in `cur/`, shared repository lock, push
   recovery after a concurrent remote update (rebase, external commit
   preserved), crash recovery of a locally moved but uncommitted transition,
   concurrent cycles importing exactly once, and read-only publish rejection.
