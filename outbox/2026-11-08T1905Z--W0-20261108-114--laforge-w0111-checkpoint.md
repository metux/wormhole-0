## Point 1 — Context-dependent YAML validation

Changed `validateYAMLKeys` from a single global `allKnown` map to per-mapping
allowed-key sets (`allKnownKeys`). Each YAML mapping path has its own allow-list:

| Path | Allowed keys |
|------|-------------|
| `wormholes` | enabled, sync, repositories |
| `wormholes.sync` | interval, startup_sync, clone_timeout, command_timeout, push_retries |
| `wormholes.repositories` | id, remote, branch, access, incoming, outgoing |
| `wormholes.repositories[]` | id, remote, branch, access, incoming, outgoing |

A key globally known (e.g., `id`, `paths`) but appearing at the wrong mapping
(e.g., `id` in `sync`, `paths` in `sync`) is now rejected as an unknown key at
that path.

Validation runs unconditionally (including when `enabled: false`). Only the
active-repository requirements (remote/branch required) remain conditional on
`Enabled`.

## Point 2 — RunLoop error propagation

instead of logging and discarding them. Errors are wrapped with context
(`syncAllRepos startup:`, `processPendingMessages startup:`,
`syncAllRepos tick:`, `processPendingMessages tick:`). Signal handling still
stops the loop gracefully via `StopDaemon()`.
